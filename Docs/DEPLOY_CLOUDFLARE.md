# Deploying to Cloudflare Pages

The Eldfall Companion App is a **static site** (a client-side React SPA — no backend server).
That means it can be hosted for free on **Cloudflare Pages**, with unlimited bandwidth, free
automatic HTTPS, and a global CDN.

- **Build command:** `npm run build`
- **Build output directory:** `dist`
- **Node version:** pinned to `22` via [`.nvmrc`](../.nvmrc)
- **No environment variables** are required.

Two things ship automatically inside `dist/` on every build:

- [`public/_redirects`](../public/_redirects) → `/* /index.html 200`, so deep links like
  `/rules/states` don't 404 on refresh (SPA fallback).
- [`public/_headers`](../public/_headers) → the Content-Security-Policy and other security
  headers that the old Express + `helmet` server used to set. Cloudflare Pages applies these
  to every response.

---

## Option A — Git integration (recommended)

This wires Cloudflare to your Git repo so every push auto-deploys.

1. Push this repo to GitHub/GitLab (any branch).
2. Log in to the [Cloudflare dashboard](https://dash.cloudflare.com/) (free account).
3. Go to **Workers & Pages → Create → Pages → Connect to Git**.
4. Pick the repository and the branch to deploy (e.g. `main`).
5. In **Build settings**:
   - **Framework preset:** `Vite`
   - **Build command:** `npm run build`
   - **Build output directory:** `dist`
   - (Node version is read from `.nvmrc`. If you ever need to force it, add an environment
     variable `NODE_VERSION = 22` under Settings → Environment variables.)
6. Click **Save and Deploy**. The first build takes ~1–2 minutes.

You'll get a free `https://<project>.pages.dev` URL. Every subsequent `git push` to the chosen
branch triggers a new deploy; pull requests get preview URLs.

---

## Option B — Direct upload with Wrangler (no Git integration)

Good for a one-off deploy from your machine.

```bash
npm run build
npx wrangler pages deploy dist
```

The project name and output dir come from [`wrangler.toml`](../wrangler.toml). The first run
prompts you to log in to Cloudflare in the browser.

To preview the built site locally exactly as Cloudflare serves it (applying `_redirects` and
`_headers`):

```bash
npx wrangler pages dev dist
```

## Connecting a custom domain

Once the Pages project is live, attach your own domain (`example.com`):

1. In the Pages project → **Custom domains → Set up a domain** → type your domain → **Continue**.
2. Then, depending on where the domain's DNS lives:
   - **DNS already on Cloudflare** (domain added to your Cloudflare account, or registered with
     Cloudflare Registrar): the required DNS record is created automatically. Done.
   - **DNS elsewhere** (GoDaddy, Namecheap, TransIP, …): either
     - move the domain's nameservers to Cloudflare (recommended — free, unlocks the CDN), or
     - add the `CNAME` record Cloudflare shows you at your current DNS provider.
3. Cloudflare issues and auto-renews a free SSL certificate. HTTPS is live within a few minutes.

**Moving an existing domain off Google:** you don't need to buy a new domain — just repoint the
one you already have. Add it to Cloudflare, update the nameservers at your registrar, then attach
it to the Pages project as above. The switch is a DNS change, not a new purchase.

## Notes & troubleshooting

- **Costs:** hosting, DNS, CDN, and SSL are all free. The only unavoidable cost is the domain
  registration itself (~€10/year), the same wherever you register it. Cloudflare Registrar sells
  at cost with no markup.
- **404 on hard refresh of a sub-route:** confirm `dist/_redirects` exists after a build (it's
  copied from `public/_redirects`). Without it, Cloudflare returns 404 for client-side routes.
- **Fonts / analytics blocked in the console:** the CSP lives in `public/_headers`. If you add a
  new external origin (a new font host, analytics, image CDN, …), add it to the matching CSP
  directive there or the browser will block it.
- **Build fails on Cloudflare but works locally:** usually a Node version mismatch — make sure
  `.nvmrc` (22) is committed, or set `NODE_VERSION = 22` in the Pages environment variables.
- **PWA:** the service worker (`vite-plugin-pwa`, `autoUpdate`) is generated by `npm run build`
  and served as static files, so offline/installable behavior works on Cloudflare Pages as-is.
